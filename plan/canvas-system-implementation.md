# 画布系统实施方案

> 日期：2024-12-23

## 一、背景

当前应用编辑器的组件直接渲染在编辑视口中，没有明确的画布边界概念。用户需要为异形屏/定制屏创建固定尺寸的应用（如 3840×2160），需要一个画布容器来承载所有组件。

## 二、核心设计

### 画布模型

```javascript
canvas: {
  width: 3840,      // 画布宽度
  height: 2160,     // 画布高度
  background: '#1a1a1a'  // 背景色
}
```

### 编辑 vs 预览行为

| 模式 | 画布渲染 | 说明 |
|------|----------|------|
| **编辑模式** | 缩放适配视口 | 开发者电脑屏幕可能较小，需要缩放显示 |
| **预览模式** | 原尺寸渲染 | 目标设备全屏显示，不缩放 |

```
编辑器 (1920×1080 窗口):            预览 (3840×2160 目标屏):
┌────────────────────────┐          ┌─────────────────────────────┐
│  ┌────────────────┐    │          │                             │
│  │ Canvas (50%)   │    │    →     │     Canvas (100%)           │
│  │ [widgets]      │    │          │     [widgets]               │
│  └────────────────┘    │          │                             │
└────────────────────────┘          └─────────────────────────────┘
```

## 六、注意事项

1. **组件坐标系**：组件的 position 相对于画布左上角，不受缩放影响
2. **Moveable 适配**：缩放后需要调整 Moveable 的坐标转换
3. **保存/加载**：画布尺寸需要持久化（已有 canvas 字段）
